# ADR-014: Centralized lock directory isolation and cross-platform I/O normalization

## Status

Accepted

## Context

Prior to Phase 6, `brain-79` suffered from two categories of filesystem issues:
1. **Visual Pollution from Adjacent `.lock` Files:** Mutex files generated by `filelock` were created adjacent to source documents (e.g. `decisions/adr-001.md.lock`, `INDEX.md.lock`, `.navigation_registry.json.lock`). Because `filelock` intentionally leaves zero-byte lock files on disk to prevent POSIX inode unlinking race conditions, content directories accumulated dozens of orphaned `.lock` files, cluttering file trees in VS Code, Obsidian, and Git clients.
2. **Cross-Platform Inconsistencies (Windows & Linux):**
   - **Linux Case-Sensitivity:** On macOS APFS, case-insensitive path lookups hid broken links such as `[ADR-001](ADR-001.md)` when the target was lowercase `adr-001.md`.
   - **Windows Backslashes:** Path inputs containing `\\` were treated on POSIX as literal single-segment filenames and contaminated navigation registries.
   - **CRLF vs LF:** Checked-out files on Windows containing `\r\n` broke exact substring replacements during `edit_article` and `session_commit`.
   - **NTFS Atomic Replace:** External indexers (antivirus, IDEs) transiently locking destination files caused atomic `replace()` operations to fail with `PermissionError`.

## Decision

1. **Dedicated Lock Manager (`src/brain79/core/locks.py`):**
   - Centralize all lock files into `.brain-79/.locks/`.
   - Implement deterministic lock naming via `get_lock_path()`:
     - `.navigation_registry.json` $\rightarrow$ `.locks/_registry.lock`
     - `.bootstrap_state.json` $\rightarrow$ `.locks/_bootstrap.lock`
     - Root and subfolder articles $\rightarrow$ `.locks/path__to__article.md.lock`
   - Exclude `.locks/` across `_EXCLUDED_DIRS` in `wiki.py`, `lint.py`, and Ripgrep searches (`-g "!.locks/**"`).
   - Add `.locks/` to `.brain-79/.gitignore`.
   - Provide `cleanup_legacy_inline_locks()` to purge legacy adjacent locks during initialization and migrations.
2. **Universal Cross-Platform I/O Boundaries:**
   - **Exact-Case Verification:** Implement `has_exact_case_path()` to verify segment-by-segment character casing against directory entries, giving 100% Linux `ext4` case-sensitivity parity on macOS APFS.
   - **Strict POSIX Path Normalization:** Route relative path generation through `.as_posix()`, ensuring `.navigation_registry.json` never contains backslashes.
   - **Strict LF Line Endings:** Normalize incoming reads with `.replace("\r\n", "\n")` and enforce `newline="\n"` on all writes (`write_text`), including `.git/hooks/pre-commit`.
   - **NTFS Replace Resilience:** Implement `atomic_replace_with_retry()` with exponential backoff on `PermissionError` across all atomic replace call sites.
   - **Hardened Git Hook:** Inject user binary PATHs into `.git/hooks/pre-commit` to ensure non-interactive shell discovery of `brain79`.

## Consequences

- **Zero Content Directory Clutter:** Content folders contain only curated Markdown articles; all lock management is transparently isolated into `.locks/`.
- **Deterministic Portability:** Identical behavior across macOS, Linux, and Windows without requiring external CI runners.
- **Robust Concurrent Multi-Agent Execution:** No lock contention collisions or registry corruption across platform boundaries.
